## Not verified

A real SAP DEV connection, permissions, deployed iFlow bundle, tenant-specific upload/version behavior, CSRF variations or live MPL results were not verified because no SAP credentials or exported bundle were supplied. Unit tests use mocked SAP HTTP responses. The demo validates the product flow, not SAP service correctness.

The unpacked extension's Chrome installation and toolbar side-panel behavior have not been manually tested in Chrome; its manifest/service worker are included and its identical panel UI was tested as a browser page. Docker build/start was not executed. Production hosting, multiple workers, external LLM providers, automatic source repair and WhatsApp are not implemented.

## Live DEV acceptance checklist

1. Configure a least-privilege service key and tenant-scoped access token; confirm package and artifact reads.
2. Confirm an unprivileged actor cannot propose/approve and a second tenant cannot read the first tenant's run.
3. Propose a disposable package, reject once and verify absence. Propose/approve a new package and read it back.
4. Export a simple known-good iFlow from SAP. Review its source and external bindings. Enable upload capability and create it under a new ID, then inspect it in the SAP designer.
5. Deploy only with permission to activate any timers/external connections. Check returned task ID, build outcome and runtime STARTED status.
6. Run the generated smoke test. Treat business transaction validation as a separate phase; no message is sent by this MVP.
7. Inspect MPL summaries with the required monitoring role. Missing recent messages is not treated as proof of failure or success.
8. Restart while waiting for approval and verify resumption. Test crash/ambiguous-write behavior only in a controlled disposable tenant; reconcile SAP outcomes before starting another plan.
9. Manually clean up disposable test artifacts through the SAP UI; deletion/undeploy is outside this MVP's tool allowlist.
